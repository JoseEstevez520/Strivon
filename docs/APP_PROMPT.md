# Prompt para construir a app (colar no Claude Code, na raiz do repo Strivon)

You are building the staff-facing app for **Strivon**, a shelf-monitoring tool for the Sensei "Fruits & Vegetables" challenge at JunctionX Lisbon 2026. Read README.md, docs/PLAN.md and docs/TASKS.md first.

## What exists
- `data/planogram.json`: {"Frutas e Legumes": {"cameras": {cam: {"products": [{area_id, product_id, product_name, image_coordinates{top_left,top_right,bottom_right,bottom_left}}]}}}}. 14 cameras, 152 areas. Coordinates are pixels in 1280x720 images, areas are perspective quadrilaterals, some coordinates negative.
- `data/images/<cam>/<unix_timestamp>.jpg`: ~13 images per camera across one day. Not committed.
- `outputs/predictions.json`: {cam: {image.jpg: {area_id: {planogram_compliant: bool, stock_level: "empty|half|full", stock_value: 0|0.5|1, fill_raw: float}}}}. Generated by `python backend/baseline.py`. The AI pipeline will keep improving it, so the app must only read this file and never assume values.
- Python venv at `.venv`; `frontend/` is empty (React + shadcn/ui planned), `backend/` has the pipeline.

## Build
1. **Backend API (FastAPI, backend/api.py)**: endpoints to list cameras, list images per camera (with human-readable time from the Unix timestamp), return an image, and return the area results for an image joined with planogram data (product name, polygon). Add `GET /shift/{timestamp}` or similar: for the latest image of every camera, a prioritised task list. Read predictions.json fresh on each request so new predictions appear without restart. Enable CORS for the dev server. Product names are Portuguese catalogue names (e.g. "BANANA CAT I CNT KG"): add a helper that prettifies them ("Banana").
2. **Frontend (frontend/, Vite + React + TypeScript + Tailwind + shadcn/ui)**: a dashboard a store employee understands in five seconds.
   - Home = "My shift": a ranked to-do list. Sections: **Restock now** (stock empty), **Low** (half), **Wrong product** (planogram_compliant false, "move back to place"), **All good** collapsed. Each card: product, camera/gondola, area number, a small cropped thumbnail of the area, one clear action, and a coloured status (red empty, orange half, green full, purple wrong product). Sort by urgency: wrong product and empty first.
   - Gondola view: the camera image with the area polygons drawn over it as SVG, coloured by status, hover/click shows product and stock. A time slider or prev/next to move through the day's images, so staff and judges can see the shelf evolve.
   - Top bar with counters: areas empty / low / wrong / ok across the store, and a per-camera heat grid.
   - Mobile-first and fast, clear typography, light and dark mode, no clutter. UI/UX is the tie-breaker in the judging, so polish matters: loading and empty states, keyboard access, good contrast.
3. **Dev experience**: `backend/` run command and `npm run dev` documented in README; a Vite proxy to the API. Tell me exactly how to start both.

## Constraints
- Do not commit data/, outputs/, .env or any key. Never put API keys in the frontend.
- Match the existing code style, small commits, work on a branch named `<your-name>/app` and open a PR to main.
- Do not change the format of predictions.json. If you need extra fields, make them optional.
- Verify by running both servers and checking the pages in the browser (screenshots) before reporting back, and say plainly what you did not test.
